# Time Around the World

An OpenHarmony clock example for phones and tablets that shows local time alongside times in selected cities.

## What this example demonstrates

| Capability | API or platform service | Where to look |
| --- | --- | --- |
| Show the device's local date, time, and time-zone label | `systemDateTime.getTime`, `i18n.getTimeZone`, `TextClock` | [Main screen](entry/src/main/ets/pages/Index.ets) |
| Show each city's current time and its difference from local time | `i18n.getTimeZone(zoneId).getOffset(timestamp)`, `TextClock` | [City catalog and offset helper](entry/src/main/ets/Data/DataSource.ets), [main screen](entry/src/main/ets/pages/Index.ets) |
| Find and select a city | `Search`, `AlphabetIndexer`, `NavDestination` | [City picker](entry/src/main/ets/pages/ListPage.ets) |
| Keep selected cities and their order across launches | `PersistentStorage`, `@StorageLink`, `ForEach.onMove` | [Main screen](entry/src/main/ets/pages/Index.ets), [saved-list restoration](entry/src/main/ets/Data/CityListLogic.ets) |

## Requirements

- An OpenHarmony device using the default or tablet module profile. The build profile compiles and targets API 23 and declares API 20 as its compatibility floor.
- Java 17, Node.js, Oniro `oniro-app` CLI 0.10.0, OpenHarmony SDK 6.1 (API 23), and OpenHarmony command-line tools for the build steps below.
- Local development signing material generated by `oniro-app sign` to install the HAP. No app permissions or external service are configured.

## Build and run

From this repository's root directory:

```sh
npm install -g @oniroproject/oniro-app@0.10.0
oniro-app sdk install 6.1
oniro-app cmdtools install
cp build-profile.example.json5 build-profile.json5
oniro-app sign
oniro-app build
oniro-app app install
oniro-app app launch
```

In PowerShell, use `Copy-Item build-profile.example.json5 build-profile.json5` instead of `cp` if `cp` is unavailable. The example profile is tracked; the generated `build-profile.json5` and `signatures/` directory are ignored by Git. The signed package is `entry/build/default/outputs/default/entry-default-signed.hap`. The generated signing material is for local development. If several devices are connected, pass `--device <serial>` to the install and launch commands.

## Use

1. Open the app to see the device's local clock and date.
2. Select **Add city**. Browse with the alphabet index or search by city name, then select a city. Search is case insensitive; for example, `warsaw` matches Warsaw rather than every city sharing its time zone.
3. Add more cities. A check mark in the picker identifies cities already selected; selecting one again leaves the list unchanged.
4. Touch and hold any clock row, then drag it to reorder. Reordering works in normal and Edit modes. Select **Edit** to delete a city; select **Cancel** to leave Edit mode. The selected cities and their order remain after relaunch.

## Explore the implementation

[EntryAbility](entry/src/main/ets/entryability/EntryAbility.ets) loads the [main screen](entry/src/main/ets/pages/Index.ets). The main screen obtains the current time and device time-zone ID, calculates current offsets for the selected cities, and opens the [city picker](entry/src/main/ets/pages/ListPage.ets) through `Navigation`. The [catalog](entry/src/main/ets/Data/DataSource.ets) stores 573 city records and IANA time-zone IDs. [Saved-list restoration](entry/src/main/ets/Data/CityListLogic.ets) upgrades older saved entries while retaining their order.

## Verify

After installing the signed HAP on a device or emulator, compare the local clock with the device time. Add Warsaw and another city, check their clocks, then relaunch to confirm the selection persists. Drag a city to a new position, relaunch, and check its order. Search `warsaw`, clear the search, and check the full alphabetized list returns. Enter Edit mode, delete a city, and check the picker marks it as available again. If possible, change the device time zone and compare the clocks again.

## Limitations

The picker uses the cities listed in the bundled catalog; it does not download new cities or time data. Search matches city names only. The displayed times use the device clock and its installed time-zone data.

The static city catalog is derived from the GeoNames `cities1000` dump downloaded on 2026-10-21 and filtered to records with a population of at least 1,000,000. GeoNames data is licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/); see [GeoNames](https://www.geonames.org/) for the source.
